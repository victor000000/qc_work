## Verification scope

`python scripts/check_docs.py` validates public canonical local paths/anchors, ignores fenced-code examples, counts all owned prose and records unavailable historical links. It performs no network requests or operational commands. Markdown headings use a small GitHub-style slug subset; generated HTML, reference-style links and arbitrary HTML navigation are outside this checker. External URLs, provider entitlements, private evidence, historical return claims and current service/cloud state are not verified by link checks.

Source review checked CLI enum/help, configuration loader/discovery/precedence, setup/check/bootstrap scripts, locked dependency/workflow commands, access-lock/migration implementation, v090 data admission and v092 probe/receipt boundaries. Safe verification invokes only executable help/version and offline tests/checks. No account call, queue write to live data, service action, acquisition or deletion is used to validate prose.

## Self-review and remaining limits

The audit preserves dated releases and failures rather than relabeling old results. Canonical links point to public source; the handbook and dated records explicitly mark operational-only evidence references. Research packages retain their own development scope and scorer contracts. Numerical/model/cloud parity, margin/IV causes, strict provider readiness and funded/prospective acceptance remain open. A comprehensive prose inventory is not proof that every historical dataset or proposed algorithm was implemented.

This documentation phase uses a separate commit and exact-tree/CI acceptance from the implementation release. The sole publisher serializes remote updates; no new service deployment is part of documentation publication.
